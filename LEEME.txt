ESTRUCTURA
  app.py                  servidor
  crear_usuarios.py       administrar usuarios desde la terminal
  migrar_passwords.py     solo para migrar desde la versión anterior
  usuarios_iniciales.json usuarios de arranque (BÓRRALO tras usarlo)
  requirements.txt        dependencias
  .env.example            plantilla de configuración  ->  copiar a .env
  sql/                    scripts para Supabase
  templates/              index.html, login.html
  static/                 logo.png

QUÉ CAMBIÓ RESPECTO A LA VERSIÓN ANTERIOR
  • Ya no hay claves en el código: todo va en .env
  • Contraseñas cifradas (hash). Nunca más en texto plano
  • NUEVO: "Cambiar contraseña" para cualquier usuario (botón arriba a la derecha)
  • NUEVO: ventana "Usuarios" para admin: crear, cambiar rol, activar/desactivar
    y restablecer contraseñas
  • ID de Atención asignado por la base de datos (sin duplicados ni saltos por error)
  • Lista completa sin tope de 1000 filas
  • Importar Excel en una sola operación y omitiendo duplicados exactos
  • Rol "usuario": solo edita/elimina lo que él registró (admin: todo; visor: solo ver/exportar)
  • Bloqueo tras 5 intentos fallidos (10 min); sesión revalidada cada 60 s
    (si desactivas a alguien, pierde el acceso casi de inmediato)
  • Redirección tras login segura; se puede borrar un usuario sin romper registros

══════════════════════════════════════════════════════════════
 A) PRIMERA VEZ ANTES DE PUBLICAR (importante)
══════════════════════════════════════════════════════════════
  1. ROTAR la secret key de Supabase (la anterior quedó expuesta en el código
     y en chats):  Supabase -> Project Settings -> API Keys -> crear/rotar
     la secret key y desactivar la anterior.
  2. cp .env.example .env   y completar SUPABASE_SECRET (la nueva) y SECRET_KEY:
       python -c "import secrets; print(secrets.token_hex(32))"
  3. pip install -r requirements.txt

══════════════════════════════════════════════════════════════
 B) INSTALACIÓN NUEVA (base de datos vacía)
══════════════════════════════════════════════════════════════
  1. Supabase -> SQL Editor -> pegar sql/supabase_schema.sql -> Run
  2. python crear_usuarios.py --seed
  3. Borrar usuarios_iniciales.json
  4. python app.py   ->  http://127.0.0.1:5050

══════════════════════════════════════════════════════════════
 C) YA TENÍA LA VERSIÓN ANTERIOR (conserva tus registros y usuarios)
══════════════════════════════════════════════════════════════
  1. Supabase -> SQL Editor -> sql/migracion_paso1.sql -> Run
  2. python migrar_passwords.py        (convierte las contraseñas a hash)
  3. Supabase -> SQL Editor -> sql/migracion_paso2.sql -> Run
     (borra las contraseñas en texto plano)
  4. Contraseña de RogerECC (ya no comparte la de Sebastian):
       python crear_usuarios.py --cambiar RogerECC
     (te la pide por teclado: escribe  Rogercesop)
  5. python app.py

══════════════════════════════════════════════════════════════
 PUBLICAR EN PRODUCCIÓN
══════════════════════════════════════════════════════════════
  Linux/Mac:   gunicorn -w 2 -b 0.0.0.0:5050 app:app
  Windows:     waitress-serve --port=5050 app:app
  Con HTTPS:   en .env poner COOKIE_SECURE=1
  Detrás de nginx/proxy:  TRUST_PROXY=1
  Nota: el límite de intentos fallidos es por proceso; con varios workers
  cada uno lleva su propia cuenta (sigue protegiendo).

REGLAS DE CONTRASEÑA
  Mínimo 8 caracteres y distinta del nombre de usuario.
